## What happened

1. **Frame rate at 100 Hz.** The user ran Virtual Desktop at 100 fps, frame
   generation off, FOV tangent 90 per cent. Watched from the viewer's own
   log (no flags written): 64 to 75 game pairs a second in play, lowest
   windows about 58; the user saw "around 65-70". On 16 September the
   pipeline pinned near 55. One session, not a controlled comparison: the
   zone and the streaming rate both differ from the 16 September arms.
   (Corrected 18 September: those arms ran at **120 Hz**, not 90 --
   `last_display_period_ms=8` in every one of them. So the streaming rate
   fell by a sixth and the game's own rate rose by about a fifth, which
   makes the rate itself the largest performance lever found so far and is
   why the user asked for a sweep: see the 18 September detailed list.)
2. **Boards turning against the head: Virtual Desktop's quad layers at a
   cropped FOV.** No recenter in the log, so not the 16 September cause.
   Every run since the FOV tangent went to 90 per cent has it (first run
   16 September 17:39), none before (last full-FOV run 15:22). The world, a
   projection layer, was right; our boards were quad layers, which Virtual
   Desktop's compositor draws with its own projection. Fix (`85f5517`): a
   `PanelRenderer` (`src/xr/panel_renderer.*`) rasterises the board and the
   menu pointer from each frame's located eye poses and the runtime's field
   of view into two eye swapchains, submitted as a second projection layer
   blended by premultiplied alpha over the world.
   `DTVR_XR_BOARD_PROJECTION=0` restores the quads. A GPU test checks the
   geometry against first-principles projection with Virtual Desktop's
   asymmetric 90 per cent FOV. The user, worn: "board fix worked".
   Still quad layers: the gameplay reticle and the ADS vignette (small, near
   the view's centre; the user reports no issue in game).
3. **The worn checklist round.** Recorded in full, with the map between the
   user's renumbered list and the checklist's numbers, in
   [worn-results-2026-09-17.md](../phase1/worn-results-2026-09-17.md), before
   any of it was acted on (the user's instruction). Eight fixes followed,
   the same evening; that document lists each with its cause and commit.
   The checklist is now [items 39 to 46](../phase1/test-checklist-2026-09-16.md),
   written as headings so a Markdown viewer cannot renumber them.

## Things worth carrying forward

- **The FOV tangent changes the eye target (2112x2304 to 1908x2076) and so
  everything sized from it.** Two breakages so far: Virtual Desktop's quad
  layers, and the hand overlay's atlas cells (477 px instead of 528, which
  the wrist display's fixed pixel layout overflowed). Anything else laid
  out in eye-target pixels is a suspect when something looks off at a
  non-default tangent.
- **The first-person body reports third person to the equipment code**
  (`is_in_first_person_mode()` is false in VR). Stock systems that branch on
  it take their third-person path: the servo skulls' rest tables did. Look
  for this first when a stock first-person tweak has no effect.
- **The claim slot carries one request a frame and two-hand support offers
  one every frame a gun is out.** Any feature that yields to "a request"
  yields always with a gun wielded; yield to `acquire`, `approach` or a held
  grip instead (`Radial.yields`).
- **"Full body (experimental)" is the body mirror module's `overlay` mode**
  now; the older headless third-person body keeps only its dev flag.
- PowerShell 5.1 mangles a here-string commit message that contains double
  quotes when it is passed to `git commit -m`; the commit silently does not
  happen. Use `git commit -F <file>`.
