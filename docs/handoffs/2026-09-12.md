## Done today

**Remote-server mission admission** ([REMOTE-MISSION-ADMISSION-2026-09-12.md](../REMOTE-MISSION-ADMISSION-2026-09-12.md)).
The gameplay-context policy now distinguishes an established remote
authority from an unknown one (`Context.authority`: true, false, nil) and
admits mission modes under a remote dedicated server to presentation and
stock input (`body_mode`) while leaving the local-authority aim route
(`aim_mode`, `local_mission`) unchanged. The online rules admit missions under
either established authority, so a remote mission uses the same stock-input
route as Psykhanium's online rules and SoloPlay missions: dominant-hand
yaw/pitch/roll and the movement vector written into the stock fixed-frame
input cache that prediction, resend, replay and the server read, with the
server's own firing origin, actions and damage. Every local-authority
override stays off because `is_controller_aim_mode` is false whenever the
online rules are enabled. New mod setting `remote_mission_input` (default
on, read per query) withdraws it without a relaunch. The admission record
names the authority: `DARKTIDEVR_ONLINE_RULES ... authority=remote`.

## Open: the worn check on a real mission server

Not verifiable offline: there is no dedicated-server stand-in here, and the
SoloPlay mission is the local control only. Run the Ready preflight, then

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "artifacts/unattended/home-remote-mission-20260912/launch.ps1"
```

which runs the normal session with what is installed and, after exit, keeps
`console-decisive-lines.log`, `ring-phases.log` and the health log next to
the script and prints the counts of online-rules records, gameplay
deliveries, presentation-blocked lines and remote admissions. In the
mission check: hands and weapon visible and following the controllers;
movement and turning; firing where the dominant hand points; reload, dodge,
sprint, interact; a throw; button melee; the view staying with the headset
while the gun points elsewhere; and whether anything rubber-bands (a server
correction fighting the client). Hands/weapons/input absent with a
`presentation_blocked` line would mean the session's authority was not
established (check the `DARKTIDEVR_ONLINE_RULES` record); absent without
that line points at the setting.

Known limits carried from the online-rules design: ledge discovery follows
the sent hand aim; no independent weapon origins or two authoritative hand
poses; incoming correction convergence, other players' husks and official
server acceptance are only observable worn. The lifecycle checks (downing,
rescue, spectating, death, reconnect, extraction, return to hub) remain in
[MISSION-READINESS.md](../MISSION-READINESS.md).
