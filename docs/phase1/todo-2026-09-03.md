## 0. Mandatory XR preflight — always first

Before editing, building, synchronizing, launching or starting unattended work:

1. verify Virtual Desktop Streamer and VirtualDesktopXR;
2. verify exactly one authorized Quest through one working ADB client;
3. disable and then verify Quest proximity/wear automation with
   `tools\quest\set-proximity-override.ps1` using that same ADB client;
4. confirm the Quest is awake and an OpenXR session is renderable.

Treat VD suspension during Quest passthrough as normal recoverable state. Never
record the Quest serial or network address in Git.

## 5. Quantitative performance pass

Current `2496x2688` production evidence commonly delivers about 58-62 unique
stereo pairs/s once true stereo is active. Pair-driven OpenXR submissions match
fresh-pair cadence; Steam's frame-generation counter is not the number of unique
binocular pairs delivered to the runtime.

- Capture Virtual Desktop's overlay in-headset to record application/source,
  runtime/reprojection and stream/display rates separately.
- Run a matched uninstrumented fixed-pose `2496x2688` Psykhanium baseline.
- Run one bounded performance-pass trace at the same pose and analyze direct
  queue segments. Do not use the old unbounded broad resolution trace.
- Keep the timestamp-overlap warning: per-eye GPU intervals are not additive
  end-to-end pair latency.
- Attribute the current regression against the older `2112x2304` baseline only
  after accounting for the current 38% increase in stereo output pixels.
- Continue reducing duplicated second-view world/post work only where exact
  pass/resource ownership proves it safe.
- Extend the synthetic workload to a repeatable hold-forward or camera-spin hub
  path if the private-range sweep does not cover representative hub cost.
